# 本地开源投屏工具 —— 技术方案

> 版本：v1.1（v0.2 落地稿） 日期：2026-11-23
> 目标：手机投屏到电脑的本地化开源工具，支持投屏码 / 二维码 / 无线调试连接，同一局域网内点对点直连。

## 0. v0.2 架构修正（背景）

v0.1 假设「Chromium 内核浏览器均支持 `getDisplayMedia`」，实测与 MDN/caniuse 数据（2026-11）不符：**Android 所有浏览器（Chrome/Edge/百度/vivo/UC/微信等）均未实现该 API，属平台级缺失**；唯一支持的移动浏览器是 iOS 27+ Safari。因此 v0.2 增加无线投屏通道（ADB + scrcpy-server），与原 WebRTC 网页直投通道并存：

```
通道 A（Android 推荐）：无线投屏
  电脑接收页 ──ws── 信令服务(server.js + wireless.js)
                      ├─ adb pair（首次，Android 11+ 无线调试配对码）
                      ├─ adb connect + forward tcp:N localabstract:scrcpy
                      ├─ adb push scrcpy-server + app_process 拉起（raw_stream 纯 H.264 裸流）
                      └─ TCP 读取裸流 → ws 二进制转发 → 接收页 WebCodecs 解码渲染

通道 B（iOS 27+ Safari）：网页直投
  手机 cast.html getDisplayMedia → WebRTC P2P → 电脑 receive.html（v0.1 原方案）
```

## 1. 需求拆解

| 需求 | 本质 | 关键约束 |
|---|---|---|
| 手机投屏到电脑 | 手机屏幕画面实时传输到电脑显示 | 低延迟、画面连续 |
| 投屏码 / 二维码连接 | 会话匹配机制，避免手动输入 IP | 码唯一、可复用、即扫即连 |
| 同一局域网 | 点对点直连，不经过公网 | 无需 STUN/TURN 中继，延迟最低 |
| 支持红果、抖音、B站等平台 | 采集方式与目标 App 解耦，平台无感 | 采集权限由系统弹窗授权 |
| 本地使用、开源 | 无云服务依赖，代码可自由分发 | 全部本地化，零外部 CDN 依赖 |

## 2. 技术选型

对比三条路线：

1. **WebRTC 纯浏览器方案（选定 ✅）**
   - 手机 Chrome 打开投屏页 → `getDisplayMedia` 采集屏幕（含红果等任意 App 画面）→ WebRTC 点对点推流 → 电脑端页面播放。
   - 优势：无需安装手机 App、无需 ADB/Root、延迟 100~200ms、码率自适应、代码全开源可控、对 App 平台完全无感。

2. 逆向 AirPlay / Miracast 协议
   - 延迟最低，但协议未公开、实现复杂、仅限特定生态，且无法覆盖红果等国产 App 的内嵌播放，**否决**。

3. 截图 / 录屏轮询
   - 实现简单但延迟高（秒级）、画面卡顿、功耗高，**否决**。

## 3. 系统架构

```
┌─────────────┐   HTTPS   ┌─────────────┐
│  手机端页面   │◄────────►│  信令服务     │   (Node.js)
│ (Chrome 打开)│   WebSocket│ HTTPS+WS   │
│ 采集屏幕流   │           │ 投屏码匹配    │
└──────┬──────┘           └──────┬──────┘
       │ WebRTC 媒体流（局域网 P2P 直连，不经过服务端）
       ▼
┌─────────────┐
│  电脑端页面   │  接收并全屏播放（HTTP localhost）
└─────────────┘
```

- **信令服务**（Node.js，双端口）：
  - **8080（HTTP）**：电脑端接收页。localhost 被浏览器视为安全上下文，无需证书；
  - **8081（HTTPS）**：手机端投屏页。`getDisplayMedia` 仅在安全上下文开放，手机访问局域网 IP 必须走 HTTPS；使用自签名证书（首次启动自动生成，SAN 含 localhost 与全部本机地址），手机首次访问点「继续前往」即可；
  - 非本机 HTTP 请求 302 跳转到对应 HTTPS 地址；
  - 生成 6 位投屏码，服务端保存会话状态；
  - 为电脑端生成二维码（内容 `https://<电脑局域网IP>:8081/cast?code=XXXXXX`）；
  - 通过 WebSocket 匹配手机端与电脑端，转发 WebRTC 协商消息（SDP offer/answer、ICE candidate）。
- **媒体流**：WebRTC P2P 直连，**不经过服务端**，局域网内延迟与带宽最优。
- **红果适配（第一阶段目标）**：手机在红果 App 内播放视频时，投屏页以 `getDisplayMedia` 采集「整个屏幕」，红果画面原样上屏。采集方式与 App 无关，**天然覆盖抖音、bilibili 等全部平台**，无需针对单个平台做适配。

## 4. 连接流程（时序）

```
电脑端                    信令服务                  手机端
  │ 打开接收页(localhost)       │                        │
  │──请求投屏码─────────────►│                        │
  │◄──投屏码+二维码DataURL───│                        │
  │ 展示投屏码/二维码          │                        │
  │                          │                        │ 扫码打开 https://IP:8081/cast?code=XXXXXX
  │                          │◄─── WSS 连接(携带code) ──│
  │                          │ 校验码匹配               │
  │◄────── WS：有设备来投屏 ─│─────── WS：可以投屏 ────►│
  │                          │                        │
  │◄═════ WebRTC 协商（SDP/ICE，经信令转发）═════►│
  │◄════════════ WebRTC 媒体流（P2P 直连）═══════════►│
  │ 接收画面，全屏播放          │                        │ 屏幕采集中
```

1. 电脑端打开接收页 → 信令服务分配 6 位投屏码并返回二维码（DataURL，页面本地渲染，无外部请求）。
2. 手机扫码（微信/相机等任意扫码工具）→ 自动打开投屏页（HTTPS，首次点「继续前往」确认证书）→ 自动携带投屏码建立 WebSocket。
3. 服务端校验投屏码匹配 → 分别通知两端，手机端弹出系统屏幕采集授权。
4. 两端 WebRTC 协商 → 授权通过后画面实时上屏，电脑端可全屏、静音切换。

## 5. 关键设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 投屏码格式 | 6 位数字 | 输入/扫码都方便，空间足够 |
| 二维码生成位置 | 服务端生成 PNG DataURL | 页面零依赖、完全离线可用 |
| WebRTC 编解码 | 浏览器默认（VP8/VP9/H.264） | 无需额外编码库，浏览器原生支持 |
| 信令通道 | WebSocket（ws + wss 双挂载） | 双向、低延迟，与页面同协议同端口部署 |
| **双端口 HTTP/HTTPS** | 8080 电脑端 HTTP（localhost 即安全上下文）+ 8081 手机端 HTTPS（自签名证书） | 屏幕采集 API 仅在安全上下文开放；电脑端免证书免警告，手机端首次点「继续前往」即可 |
| 会话模型 | 一个投屏码对应一次会话，先到先服务 | 简单可靠；多设备扩展留待 v2 |
| 断线处理 | 电脑端断开后投屏码失效，重新打开生成新码 | 防止旧码被误用 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 手机经 `http://局域网IP` 访问（非安全上下文），浏览器不开放 `getDisplayMedia` | 所有 Chromium 内核浏览器均提示不支持，无法采集屏幕 | 手机端单独提供 HTTPS 端口（8081），自签名证书首次访问点「继续前往」；电脑端 localhost 天然安全上下文 |
| 部分国产手机浏览器内核不支持 `getDisplayMedia` | 无法采集屏幕 | **事实修正（2026-11）**：Android 平台所有浏览器（Chrome/Edge/百度/vivo/UC/微信等）均未实现 `getDisplayMedia`，属平台级缺失，升级/换浏览器无法解决；Android 改用无线调试（ADB）+ scrcpy-server 通道，iOS 27+ Safari 可用网页直投 |
| 自签名证书被手机浏览器拦截 | 无法进入投屏页 | SAN 覆盖 localhost 与全部本机地址；首次访问点「继续前往」即可（该警告与屏幕采集能力无关） |
| 系统录屏授权弹窗被拒 | 无画面 | 页面给出授权引导，拒绝后可重新触发 |
| 路由器 AP 隔离 / 双频路由 2.4G 与 5G 不互通 | 两端连不上 | 两端均有连接超时提示，文档给出排查指引 |
| 本地环境公网 CDN 不稳定 | 页面白屏 | 所有前端资源本地化，零外部依赖 |
| 无 STUN/TURN | 跨网段无法互联 | 本工具定位同局域网，文档明示边界；预留配置项 |

## 8. 范围边界（v0.1）

- **包含**：手机→电脑单向投屏、投屏码+二维码、局域网 P2P、红果验证（架构天然支持全平台）、全屏播放、静音切换、断线提示。
- **不包含**：反向控制（电脑操控手机）、声音投屏、跨网段投屏、一对多投屏、手机端 App 形态。以上列入 v2 候选。
