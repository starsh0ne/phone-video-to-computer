# local-cast 测试验收标准

> 版本：v0.1.0 日期：2026-11-22
> 适用范围：本地开源投屏工具（手机 → 电脑，WebRTC 局域网方案）

## 1. 测试环境

| 项 | 要求 |
|---|---|
| 电脑 | Windows / macOS / Linux，Node.js ≥ 18，现代浏览器（Chrome 系） |
| 手机 | Android 或 iOS，Chrome 浏览器（国产浏览器需验证 getDisplayMedia 支持） |
| 网络 | 手机与电脑处于同一局域网，路由器未开启 AP 隔离 |
| 测试范围 | 功能、信令、WebRTC 媒体链路、异常场景、性能指标 |

## 2. 功能验收项（必过项）

### 2.1 投屏码与二维码

| 编号 | 验收项 | 验收标准 | 方法 |
|---|---|---|---|
| F-01 | 投屏码生成 | 电脑端打开接收页，显示 6 位数字投屏码 | 目视检查 |
| F-02 | 二维码生成 | 页面显示可识别的二维码，扫码内容为 `http://<局域网IP>:8080/cast?code=<投屏码>` | 扫码验证 |
| F-03 | 投屏码刷新 | 点击「重新生成投屏码」，码与二维码同步更新 | 目视检查 |
| F-04 | 页面离线性 | 页面加载无任何外部网络请求（无 CDN、无字体外链） | 开发者工具 Network 面板检查 |

### 2.2 连接与信令

| 编号 | 验收项 | 验收标准 | 方法 |
|---|---|---|---|
| C-01 | 扫码连接 | 手机扫码自动打开投屏页，自动携带投屏码连接信令服务 | 真机操作 |
| C-02 | 手动输码 | 手机端手动输入 6 位投屏码可正常连接 | 真机操作 |
| C-03 | 会话匹配 | 两端就位后互相收到「对端就绪」通知，手机端「开始投屏」按钮解禁 | 真机操作 |
| C-04 | 无效码拒绝 | 使用错误/过期投屏码连接，收到明确错误提示且连接被关闭 | 自动化测试 + 真机 |
| C-05 | 断线通知 | 手机端断开后电脑端收到「手机已断开」通知，画面清理 | 自动化测试 + 真机 |
| C-06 | 码失效机制 | 电脑端关闭页面后，旧投屏码不可再用 | 自动化测试 |

### 2.3 投屏核心链路

| 编号 | 验收项 | 验收标准 | 方法 |
|---|---|---|---|
| M-01 | 屏幕采集授权 | 点击「开始投屏」弹出系统采集授权，选择「整个屏幕」后授权成功 | 真机操作 |
| M-02 | 画面上屏 | 手机画面（含红果 App 播放界面）实时显示在电脑端 | 真机操作 |
| M-03 | 红果验证（第一阶段重点） | 红果 App 播放视频时投屏，电脑端画面与声音表现正常、无黑屏 | 真机操作 |
| M-04 | 平台通用性 | 抖音 / bilibili 等其他 App 画面同样可投（架构天然支持，抽测 1-2 个） | 真机操作 |
| M-05 | 全屏播放 | 电脑端全屏按钮可进入/退出全屏，画面自适应 | 真机操作 |
| M-06 | 静音切换 | 声音开关可切换电脑端音频输出 | 真机操作 |
| M-07 | 停止投屏 | 任一端停止后，画面与采集同步结束，可重新发起 | 真机操作 |

### 2.4 异常与边界场景

| 编号 | 验收项 | 验收标准 | 方法 |
|---|---|---|---|
| E-01 | 授权拒绝 | 拒绝采集授权后，页面给出可理解的提示，按钮恢复可重试 | 真机操作 |
| E-02 | 浏览器不支持 | 无 getDisplayMedia 的浏览器打开投屏页，页面明确提示改用 Chrome | 真机/模拟 |
| E-03 | 中途断开 | 投屏中手机断网/关闭页面，电脑端显示连接中断而非假死 | 真机操作 |
| E-04 | 服务未启动 | 直接打开页面（无服务），页面给出明确错误提示 | 真机操作 |
| E-05 | 重复连接 | 同一投屏码同角色重复连接，旧连接被顶替 | 自动化测试 |

## 3. 性能验收指标（参考项）

| 指标 | 目标值 | 测量方法 |
|---|---|---|
| 信令建连延迟 | 手机连接后 ≤ 1s 内收到就绪通知 | 日志时间戳 |
| 画面首帧延迟 | 授权通过后 ≤ 2s 出画 | 真机观察 |
| 操作响应延迟 | 手机画面操作到电脑端变化 ≤ 300ms（主观无感延迟） | 真机观察 |
| 持续稳定性 | 连续投屏 30 分钟无断流、无画面卡死 | 长时间观察 |
| 资源占用 | 服务端内存 ≤ 100MB；电脑端页面正常负载 | 任务管理器 |

## 4. 自动化测试验收

- 命令：`npm test`（无浏览器依赖，Node 环境直接运行）
- 当前覆盖：HTTP 页面可访问性、投屏码/二维码接口、信令会话匹配、WebRTC 信令转发、无效码拒绝、断线通知、投屏码失效。
- **准入标准**：全部用例通过（当前 16 项，0 失败）。
- **说明**：自动化测试覆盖信令层与传输层；画面采集与实际投屏链路（M-01~M-07）需真机手动验收，因涉及系统权限弹窗与真实屏幕采集，无法纯自动化替代。
