# local-cast · 本地开源投屏工具

手机投屏到电脑的本地化工具：**投屏码 / 二维码连接，同一局域网 WebRTC 点对点直连**，媒体流不经过服务端，延迟低、无云端依赖，代码全开源。

## 特性

- 🔢 **投屏码连接**：电脑端生成 6 位投屏码，手机端输入即连
- 📱 **二维码扫码**：手机扫码自动打开投屏页，即扫即连
- 🖥️ **局域网直连**：WebRTC 点对点传输，媒体不经过服务端
- 🎬 **平台无感**：基于系统屏幕采集，红果、抖音、bilibili 等任意 App 画面均可投（第一阶段以红果验证）
- 📡 **无线投屏（Android）**：经无线调试（ADB）+ scrcpy 通道直取屏幕视频流+手机声音，无需手机装 App，不受浏览器限制
- 🍎 **浏览器直投（iOS）**：iOS 27+ Safari 支持 `getDisplayMedia`，扫码后可直接投屏
- 📴 **完全本地**：无云服务、无 CDN 依赖，前端资源全本地化

## 快速开始

### 1. 启动服务

```bash
npm install     # 首次运行安装依赖
npm start       # 或双击 start.bat（Windows 一键启动）
```

服务采用双端口设计：**8080（HTTP，电脑端）** + **8081（HTTPS，手机端，安全上下文）**。自签名证书首次启动自动生成于 `certs/` 目录。

### 2. 电脑端

浏览器打开 **http://localhost:8080/**，页面显示投屏码与二维码。

### 3. 手机端

- **方式一（推荐）**：用手机扫码工具扫描电脑端页面上的二维码，自动打开投屏页
- **方式二**：手机浏览器访问 `https://<电脑局域网IP>:8081/cast`，输入 6 位投屏码

> **关于 HTTPS 证书**：手机端必须通过 HTTPS 访问（屏幕采集 API 仅在安全上下文开放）。自签名证书首次访问会提示安全警告，点击**「继续前往」**即可，之后不再提醒。

### 4. 开始投屏

**Android 手机（推荐：无线投屏通道）**

1. 手机：设置 → 关于手机 → 连点「版本号」7 次开启开发者选项 → 开发者选项 → 打开「无线调试」
2. 电脑：接收页点击「无线投屏」→ 点「① 扫码配对（推荐）」生成二维码
3. 手机：用相机扫描电脑上的二维码 → 在手机弹窗中点「开始配对」→ 电脑自动完成配对并连接
4. 或使用「② 配对码配对」：手机无线调试 → 「使用配对码配对设备」，把弹窗中显示的 IP:端口 与 6 位配对码填入电脑接收页（注意配对弹窗与无线调试主页的端口不同）
5. 连接成功后手机屏幕画面实时显示在电脑端，可全屏观看

> 配对仅需一次，之后同一手机重开无线调试即可直接连接。首次使用会自动下载 adb（platform-tools）与 scrcpy-server 并缓存到 `tools/` 目录；也可手动下载放至 `tools/`（详见下文「工具链说明」）。投屏期间手机与电脑需在同一 Wi-Fi，或手机连接电脑发出的热点。

**iOS 27+ Safari（网页直投通道）**

扫码或输入投屏码打开投屏页 → 点「开始投屏」→ 系统弹窗选择「整个屏幕」并授权 → 画面实时投到电脑端。

> Android 浏览器均不支持网页屏幕采集（平台限制，详见上方兼容性说明），Android 请使用无线投屏通道。

## 浏览器兼容性（重要事实）

网页屏幕采集 API（`getDisplayMedia`）在移动端的支持情况（截至 2026-11，MDN / caniuse 数据）：

| 浏览器 | 平台 | 网页投屏 | 说明 |
|---|---|---|---|
| Safari | iOS 27+ | ✅ 支持 | **唯一**支持 `getDisplayMedia` 的移动浏览器 |
| Chrome | Android | ❌ 不支持 | Chromium 移动版从未实现该 API（Chrome 157 仍不支持） |
| Edge | Android | ❌ 不支持 | 同上，平台级缺失 |
| 百度 / vivo / UC / QQ / 华为等 | Android | ❌ 不支持 | 同上 |
| 微信内置浏览器 | Android / iOS | ❌ 不支持 | X5 内核 + 平台限制 |
| Firefox / Samsung Internet | Android | ❌ 不支持 | 同上 |

> **为什么手机扫码后提示「当前版本未启用屏幕采集接口」？**
> 这**不是**浏览器版本旧，也不是自签名证书问题：Android 平台的所有浏览器都未实现 `getDisplayMedia`（Chromium 移动版长期不提供屏幕采集），升级浏览器、更换 Chrome/Edge、忽略证书警告都无法解决。iOS 27+ 的 Safari 是唯一例外。

因此本项目提供两条投屏通道：

1. **无线投屏通道（Android 推荐）**：电脑端通过无线调试（ADB）+ scrcpy-server 直接读取手机屏幕视频流与手机声音（声音在电脑端播放，Android 11+ 支持），不经浏览器，不受上述限制，红果/抖音/B站等任意 App 均可投。首次使用需在手机上开启「开发者选项 → 无线调试」并完成一次配对；之后每次打开接收页会自动回填并连接上次的地址，无需重复输入。
2. **网页直投通道（iOS 27+ Safari）**：扫码 → 授权屏幕采集 → WebRTC 点对点推流到电脑。

## 工作原理

```
手机端页面 ──(信令: 投屏码匹配/SDP/ICE)──► 信令服务 ──► 电脑端页面
手机端页面 ──(媒体: WebRTC P2P 直连)─────────────────────► 电脑端页面
```

1. 电脑端打开接收页（`http://localhost:8080`），向服务申请**投屏码**，服务生成二维码（内容为带码的 HTTPS 投屏链接）
2. 手机扫码/输码连接（`https://<IP>:8081/cast`，HTTPS 安全上下文），服务校验投屏码并匹配两端会话
3. 两端通过信令服务交换 WebRTC 协商消息，随后媒体流**点对点直连**，不经过服务端
4. 手机端通过 `getDisplayMedia` 采集屏幕（任意 App 画面），电脑端接收并全屏播放

**为什么手机端要 HTTPS**：浏览器只在安全上下文（HTTPS / localhost）开放 `getDisplayMedia` 屏幕采集 API。电脑端用 localhost 天然满足；手机访问局域网 IP 必须走 HTTPS，因此服务端为手机端单独提供 HTTPS 端口（8081），自签名证书首次访问点「继续前往」即可。

## 工具链说明（无线投屏）

无线投屏通道依赖两个文件，首次使用时自动下载（需联网），缓存在 `tools/` 目录，之后完全离线：

| 文件 | 说明 | 下载源（依次回退） |
|---|---|---|
| adb（platform-tools） | 无线配对/连接/转发 | dl.google.com → 腾讯镜像 |
| scrcpy-server v5.0.1 | 手机端屏幕采集（Java，无需安装） | GitHub Releases → ghfast/gh-proxy/ghproxy 加速 |

也可手动准备：本机已装 adb（在 PATH 中）则直接复用；或用环境变量 `LOCALCAST_ADB` 指定 adb.exe 路径；scrcpy-server 放至 `tools/scrcpy-server` 即可跳过下载。

> 注：当前工具沙箱环境无法验证下载链路，首次真实使用时如下载失败，请按上方说明手动放置文件。
